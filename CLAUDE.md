# CLAUDE.md — Smart Contracts (Foundry/Solidity)

## Stack

Solidity 0.8.x · Foundry · OpenZeppelin v5 (standard + upgradeable) · ERC1967 Transparent Proxy · Arbitrum Sepolia

## Commands

```bash
forge build              # compile (optimizer + via_ir enabled)
forge test               # run all tests
forge test -vvvv         # verbose with traces
forge fmt                # format
anvil                    # local chain
./bin/run-all.sh         # deploy all contracts (10-step orchestration)
./bin/export-abi.sh      # export ABIs to abi/
```

```

├── core/
│   ├── centuari/

│   │   ├── CentuariBondERC20.sol        # Bond token (ERC20)
│   │   └── CentuariBondERC20Factory.sol # Bond token factory
│   └── settlement/
│       ├── Settlement.sol               # Batch settlement processor (upgradeable)
│       └── SettlementStorage.sol        # Storage layout with gap
├── interfaces/

│   └── ITreasury.sol
├── libraries/

├── mocks/

```

### Contract Relationships

```
Treasury (AccessControl, non-upgradeable)
  ↑ token custody
Centuari (Upgradeable, ERC1967 proxy)
  ├── creates positions via settleMatch()
  ├── uses CentuariBondERC20Factory to mint bond tokens
  └── calls Treasury for token transfers
Settlement (Upgradeable, ERC1967 proxy)
  ├── validates + batches matches
  └── calls Centuari.settleMatch() per match
```

### Market Identification

Markets are identified by `bytes32 marketId = keccak256(abi.encode(loanToken, maturity))`. Same loan token with different maturities = different markets.

## Code Standards

### Naming

| Element | Convention | Example |
|---------|-----------|---------|
| Contracts | PascalCase | `Centuari`, `Settlement`, `Treasury` |
| Interfaces | `I` prefix + PascalCase | `ICentuari`, `ISettlement`, `ITreasury` |
| Storage contracts | `*Storage` suffix | `CentuariStorage`, `SettlementStorage` |
| Functions (external) | camelCase | `settleMatch`, `repay`, `withdrawLendPosition` |
| Functions (internal) | `_` prefix + camelCase | `_processMatch`, `_getMarketId` |
| Events | PascalCase | `MarketCreated`, `LendPositionCreated`, `MatchSettled` |
| Errors | PascalCase | `AlreadySettled`, `ContractPaused`, `InvalidMaturity` |
| Constants | SCREAMING_SNAKE_CASE | `RATE_PRECISION`, `SECONDS_PER_YEAR` |
| Storage variables | `_` prefix + camelCase | `_settlement`, `_treasury`, `_marketTotalCbt` |
| Modifiers | camelCase | `onlySettlement`, `onlyOperator`, `whenNotPaused` |
| Structs | PascalCase | `MatchData`, `MarketInfo` |
| Mappings | `_` prefix + descriptive | `_settledMatches`, `_lendPositionCbtAmount` |
| Deploy scripts | `Deploy{Contract}.s.sol` | `DeployCentuari.s.sol` |
| Test files | `{Contract}.t.sol` | `Centuari.t.sol`, `Settlement.t.sol` |

### Clean Code Rules

1. **Separate storage from logic** — upgradeable contracts use `*Storage.sol` abstract contracts. All state variables live in storage contracts with `uint256[N] private __gap` for future upgrades.
2. **Interface-first design** — define all external functions in `interfaces/`. Contracts implement interfaces. Other contracts interact through interfaces, never concrete types.
3. **Access control via modifiers** — use `onlySettlement`, `onlyOperator`, `onlyCentuari`, `whenNotPaused`. Never inline access checks in function bodies.
4. **Custom errors over require strings** — use `error AlreadySettled()` over `require(!settled, "already settled")`. Custom errors are cheaper and more precise.
5. **Events for all state changes** — emit an event for every externally visible state mutation. Off-chain indexers depend on these.
6. **SafeERC20 for all transfers** — always use `SafeERC20.safeTransfer` / `safeTransferFrom`. Never call `transfer` directly.
7. **`initialize()` over constructor** — upgradeable contracts use `initializer` modifier. Use `_disableInitializers()` in constructor to prevent implementation initialization.
8. **ERC7201 for reentrancy guard** — the custom `ReentrancyGuardUpgradeable` uses namespaced storage to avoid storage collisions with proxy patterns.
9. **Rates in basis points** — all rates use `RATE_PRECISION = 10000`. 500 = 5%. Never use raw percentages or floating point.
10. **No magic numbers** — define constants for all numeric values. `365 days` not `31536000`.

### Upgrade Safety

- Never reorder or remove storage variables in `*Storage.sol` — only append
- Always maintain the `__gap` array and reduce its size when adding new variables
- Test upgrades with `UpgradeSettlement.s.sol` pattern — deploy new implementation, call `upgradeAndCall`
- ProxyAdmin controls upgrades — separate from contract owner

### Deployment Rules

- `run-all.sh` orchestrates the full deployment in 10 steps — maintain this order
- Each script is idempotent where possible — re-running should not break state
- Deployment output goes to `deployments/deploy-<network>-latest.json`
- After deployment, run `export-abi.sh` to update ABI files for off-chain services

### Testing Rules

- Use `forge-std/Test.sol` with `vm` cheatcodes
- Test files in `test/` with `.t.sol` suffix
- Use mock contracts for external dependencies (e.g., `MockTreasury`)
- Test all access control paths — verify `onlySettlement`, `onlyOperator` revert correctly
- Test upgrade paths — verify storage layout compatibility
- Test edge cases: zero amounts, expired maturities, duplicate settlements

### Configuration

```toml
# foundry.toml
via_ir = true       # IR-based code generation (required for complex contracts)
optimizer = true    # Optimizer enabled for gas efficiency
```
